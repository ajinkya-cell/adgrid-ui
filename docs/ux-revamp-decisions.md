# UX Revamp — Decisions Log

Started 2026-10-23. Running record of what we found and what we decided for the
Void UI docs site (`apps/docs`). Update this file as decisions change.

---

## 1. Feedback we received

- "The website is not easy to navigate."
- "The landing page should showcase components instead of what it shows now."

## 2. Diagnosis (from reading the code)

| # | Problem | Where |
|---|---------|-------|
| 1 | Landing page is a bio + creator story; components only appear at the bottom as a plain text list with no visuals. | `src/app/page.tsx` |
| 2 | Present mode is a dead end: the global navbar is hidden on `/present/*` and nothing links back to Home / Gallery / Docs. Only `Esc` exits (to `/gallery`), which nobody discovers. **Most likely cause of the "hard to navigate" feedback.** | `src/components/site/SiteChrome.tsx` |
| 3 | "Gallery" and "Components" in the navbar both mean "components". "Components" drops you straight into Void Button with no context. | `src/components/site/Navbar.tsx` |
| 4 | Docs (Getting Started, Installation, Theming) are not linked in the navbar at all; `/docs` highlights "Components" instead. | `Navbar.tsx` |
| 5 | The component list in present mode hides behind a decorative gauge trigger that doesn't read as a menu. | `src/components/presentation/SidebarTrigger.tsx` |

## 3. Plan (priority order)

1. **Landing page → components first.** Headline + one-line pitch, two CTAs
   (*Browse components*, *Get started* with the `npx` snippet), then a grid of
   6–9 live previews. Creator section moves to a small footer block or `/about`.
2. **Escape hatch in present mode.** Small persistent pill top-left:
   logo → home, "← All components", breadcrumb `Category / Component`.
3. **Navbar = `Components · Docs · Roughly` + Search + GitHub.**
   "Components" goes to the gallery grid. "Docs" is a real item with its own active state.
4. **Label the sidebar trigger** ("Components" / list icon) and show a one-time ⌘K hint.
5. **Polish:** category filter chips on the gallery, prev/next at the bottom of each
   component, and link or `noindex` the stray pages (`/lab`, `/hero-demo`, `/matrix-demo`).

## 4. How to show component previews (replacing iframes)

**Problem with iframes:** each `GalleryIframePreview` boots a full `/embed/[slug]`
page (its own React, fonts, CSS). The gallery has 22 of them, which explains the
loading spinners and the weight. They also have `pointer-events-none`, so visitors
can't interact with them.

**Decision: hybrid.**

- **Light, interactive components** (buttons, knobs, cards, text effects, date picker,
  wheel picker) → **render inline as real React**, imported from `@adgrid-ui/ui`.
  - Lazy-mount with `useInView` + `next/dynamic`; unmount when off screen.
  - Wrap each preview in `transform: translateZ(0); contain: layout paint` so
    `position: fixed` / `100vh` components stay inside their card.
  - Reuse the per-slug scale table from `src/app/embed/[slug]/page.tsx`.
- **Heavy WebGL / shader / canvas components** (Matrix Rain, Globe, Spotlight Text,
  Floating Embers, Breathing Grid) → **looping video + poster, swap to live on hover/tap**.
  Browsers allow only about 16 WebGL contexts at once, so these can't all run together.
- Remove the fake hand-drawn previews in `GalleryCardPreview.tsx`.

### Videos

- Generated by script: Playwright (installed, Chromium 1248) records `/embed/<slug>?mode=gallery`
  in a **headed** browser (headless WebGL renders poorly) → ffmpeg (installed) trims each clip to a
  seamless 3–5 s loop.
- Output per component: `.webm` + `.mp4` (Safari) + `.jpg` poster →
  `apps/docs/public/previews/videos/`.
- Encoding targets: about 800px wide, 24–30 fps, no audio, **≤ 600 KB per file**.
- Playback: `muted loop playsInline preload="none"` + poster; play when in view, pause
  when out; `prefers-reduced-motion` → poster only.
- If an automated capture comes out choppy, record that one by hand and run it through the same ffmpeg step.

### Vercel free (Hobby) plan — confirmed OK

- Files in `public/` are **not** in the JS bundle; they're static assets served from the CDN
  and only downloaded when a card comes into view.
- Total for about 5 components: about 3–6 MB. Fine for the repo and deployment size.
- The real limit is bandwidth (Hobby: about 100 GB/month; check the Vercel usage dashboard for the current figure).
  At about 2 MB of video per full landing-page visit, that's about 50k full visits/month from video
  alone, and browser caching stretches it further. If we outgrow it, move only the videos
  to Cloudinary or Cloudflare R2.

## 5. Gallery card redesign

Reference: a framed card with a raised inner "well" holding the preview and the name underneath
(the paid-badge icon from the reference is dropped for now).

**Anatomy**

```
┌──────────────────────────────┐  outer frame: #141414, radius 30px, faint top-lit border
│ ┌──────────────────────────┐ │  14px padding (radii stay concentric: 30 ≈ 18 + 14)
│ │                          │ │
│ │       [ component ]      │ │  well: #1c1c1c, radius 18px, raised (lighter than frame)
│ │                          │ │
│ └──────────────────────────┘ │
│  Component name          →   │  title: Poppins 15px medium, arrow fades in on hover
└──────────────────────────────┘
```

**How the component sits inside the well**

- The well is the component's "stage": `flex-1`, `overflow-hidden`, and it clips to its radius.
- **Object components** (buttons, knobs, cards): centered, with padding so they never touch the
  well's edges; scaled to fit (`padded`, the default).
- **Canvas / background components**: fill the well edge to edge (bleed) and are clipped by
  the radius. No floating badge; the name sits below like on every other card.
- **Iframe previews (for now)**: rendered edge to edge because `/embed?mode=gallery` already
  centers and scales the component; its gallery-mode background matches the well colour (`#1c1c1c`)
  so the preview blends into the well.
- Hover: the card lifts 5px and the well brightens slightly. No coloured category glow.
- It is a library component: **`PreviewCard`** (`packages/ui/src/primitives/PreviewCard.tsx`, slug
  `preview-card`, in the Cards group of present mode). Colours, radius, inset, arrow and lift are props;
  `as={Link}` makes it a Next link; `badge` is an optional top-right slot (where the reference had the
  dollar icon). The preview is passed as `children`, so swapping iframe → inline/video later doesn't
  touch the card.

## 6. Gallery revamp

- Width capped at **1160px** (was 1600px), so cards stay a comfortable size.
- **Sections = the present-mode navigator groups** (`PRESENTATION_GROUPS`), each with an icon, label and count.
- **Curated, not everything: exactly 50 components**, only ones that read well at card size. The list and
  each card's size live in `apps/docs/src/app/gallery/showcase.ts` (`GALLERY_SHOWCASE`). Pages (full
  heroes) and Preview Card are left out. The header links to all 108 in the navigator.
- **Bento layout:** sizes `sm` (1×1), `wide` (2×1), `tall` (1×2), `lg` (2×2) on a 3-column grid, 260px
  rows. Every section adds up to whole rows (a multiple of 3 cells), so there are no holes. Keep that true when
  editing the list. On phones everything is one column.
- **Section chip bar removed.** It was crowded and added little once the page got shorter.
- **Previews auto-fit:** gallery-mode embeds wrap the component in `FitToFrame`
  (`apps/docs/src/components/site/FitToFrame.tsx`), which lays it out at least as wide as the card well and
  scales it down to fit. This replaced the hand-tuned per-slug gallery scale table in `embed/[slug]`, so any
  card size works without tuning.
- Swapped out after screenshot review (don't work at card size): command-palette (tiny closed trigger),
  ruler-nav, charts and bento-grid (long multi-demo stacks), stacked-card-fan and image-reveal (need
  scrolling), tilted-collage, moon-pull, marquee, marquee-2, image-parallax.
- Iframes unmount when scrolled off screen (150px margin) to keep memory and WebGL contexts down.
